# Hub 存储阶段 1：SQLite → PostgreSQL 评审级设计

> 状态：评审级设计（未实现）
> 前置：`architecture.md`（HA 选项调研，推荐 PG + DB 租约路线）
> 本文是 `add-hub-postgres-storage` 实施 change 的蓝图。纯设计；行号引用基于当前 `crates/arkflow-server/src/storage.rs`。

## 1. 现状事实（精读结论）

| 事实 | 位置 | 设计影响 |
|------|------|---------|
| 入口：`ARKFLOW_HUB_STORAGE` env 存文件路径 → `ControlPlaneStore::open(path)` | `bin/arkflow-server.rs:24,35-37` | 配置面按 scheme 分派即可，零新配置键 |
| SQLite 调参：WAL / synchronous=NORMAL / foreign_keys=ON / busy_timeout=5s | `storage.rs:1731-1735` | PG 侧对应连接池参数设计（§6） |
| 17 张 `cp_*` 表，DDL 全部 `CREATE TABLE IF NOT EXISTS` 内联于 `migrate()` | `storage.rs:3449-3680` | PG 侧同策略：启动时执行幂等 DDL（§4） |
| 3 张表用 `INTEGER PRIMARY KEY AUTOINCREMENT`（cp_events / cp_audit_events / cp_outbox） | DDL | PG → `BIGINT GENERATED BY DEFAULT AS IDENTITY`；`last_insert_rowid()`（仅 `storage.rs:2740` 一处）→ `RETURNING event_id` |
| 唯一显式事务：`transaction_with_behavior(Immediate)` 一处（操作+outbox 原子追加） | `storage.rs:1762` | PG → 普通 `BEGIN`（首写即取写锁，无需 IMMEDIATE）；其余全部单语句 |
| 部分/条件唯一索引：`cp_one_active_attempt` 等依赖终端 attempt 被清理 | `storage.rs:1362,2316` | PG 原生支持 partial unique index，语义直译 |
| StorageActor 是 **tokio 任务**（非独立线程），FIFO 逐条处理命令，同步 rusqlite 调用直接写在 match 臂内 | `storage.rs:607-700` | actor 保留；match 臂改为 await backend trait 方法，FIFO 顺序不变性保持（§3） |
| `StorageCommand` 变体 ~52 个，`oneshot` 回传 `Result<T, StorageError>` | `storage.rs:363-605` | 命令面不动；仅 `StorageError` 增加 `Pool(#[from] sqlx::Error)` 变体 |
| `cp_outbox.event_key UNIQUE` 提供事件去重；`cp_attempts.command_id UNIQUE` 幂等 | DDL | PG 同构，注意大小写/排序规则差异（§5.3） |

## 2. 目标与非目标

**目标**：Hub 的控制面存储可选 PostgreSQL；SQLite 保持默认且零行为变化；数据可一次性迁移；两种后端共享同一契约测试套件。
**非目标**：leader election（阶段 2）；Agent 多 Hub 发现；读扩展/流复制运维方案；SQLite 移除。

## 3. Backend 抽象

```rust
#[async_trait]
pub trait StorageBackend: Send + Sync + 'static {
    async fn upsert_job(&self, job: JobRecord) -> Result<JobRecord, StorageError>;
    // …与 StorageCommand 一一对应的 ~52 个方法，签名不变
}

pub enum ControlPlaneStore {          // 现名保留，避免 Hub/测试大面积改名
    Sqlite(SqliteBackend),            // 现有 rusqlite 逻辑原样搬入
    Postgres(PostgresBackend),        // sqlx PgPool
}
```

- **顺序不变性**：actor 循环 `while let Some(cmd) = receiver.recv().await` 逐条 `match` 并 `await` backend 调用——仍是严格 FIFO，单写者顺序（reconciliation/rollout 依赖的操作顺序）不受影响。SQLite 实现内部沿用 `Arc<Mutex<Connection>>`；PG 实现靠 PgPool 多连接 + 事务，天然并发安全，但 actor FIFO 使行为与 SQLite 完全一致（不引入乱序回填）。
- **为什么不消除 actor**：Hub 的 reconcile/rollout/outbox 语义隐含"存储操作按提交顺序生效"；消除串行化需要逐命令证明无顺序依赖，风险远大于收益。actor 保留后两端行为可逐字节对拍。
- **事务签名**：trait 提供 `append_operation_with_outbox(...)` 这样的**复合方法**（而非暴露事务句柄），事务边界封在实现内部——SQLite 用 `BEGIN IMMEDIATE`，PG 用 `BEGIN`，调用方无感。

## 4. Schema 映射（17 表逐类规则）

| SQLite | PostgreSQL | 说明 |
|--------|-----------|------|
| `TEXT PRIMARY KEY` | `TEXT PRIMARY KEY` | 直译 |
| `INTEGER`（epoch-ms / 计数 / generation） | `BIGINT` | i64 语义，统一 BIGINT 防溢出 |
| `INTEGER PRIMARY KEY AUTOINCREMENT` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | `last_insert_rowid()` 调用点改为 `… RETURNING event_id` |
| `TEXT NOT NULL DEFAULT '…'` | 直译 | 字面量默认值兼容 |
| `BLOB`（如有） | `BYTEA` | — |
| `CREATE INDEX IF NOT EXISTS` | 同 | PG 支持幂等 DDL（`CREATE INDEX IF NOT EXISTS`，PG 9.5+） |
| `CREATE UNIQUE INDEX cp_one_active_attempt`（条件唯一） | `CREATE UNIQUE INDEX … WHERE state IN ('active', …)` | partial unique index 直译，条件表达式按现有 DDL 逐字对照 |

**排序规则/大小写**：SQLite `UNIQUE` 对 TEXT 默认二进制比较；PG 默认 collate 可能大小写不敏感排序但唯一性仍精确匹配（`C` collate 不必需）。设计要求：全部 TEXT 主键/唯一列显式 `COLLATE "C"`，保证与 SQLite 二进制语义逐字节一致（id 类字符串均为 ASCII，无本地化诉求）。
**DDL 执行**：PG 侧 `migrate()` 用 `sqlx::raw_sql` 执行与 SQLite 同构的幂等 DDL；不引入 sqlx migrate 文件机制（表结构演化仍随代码走，与现状一致）。

## 5. 一致性语义映射

1. **事务**：唯一显式事务（`storage.rs:1762`，操作+outbox 原子追加）→ PG `BEGIN … COMMIT`（默认 Read Committed 即可：该事务只做两表 INSERT，无读-改-写竞态）。SQLite 的 `IMMEDIATE` 在 PG 无对应物也无必要。
2. **唯一约束冲突**：SQLite 呈现为 `rusqlite::Error::SqliteFailure(Constraint)`，现被映射为领域错误；PG 侧 `sqlx::Error::Database` with code `23505` → 同一领域错误变体。实现须建「冲突错误映射表」测试（intents 幂等、attempts command_id 幂等、outbox event_key 去重三处）。
3. **busy 语义**：SQLite `busy_timeout=5s`（写写冲突等待）→ PG 无对应物（MVCC 不阻塞读写）；连接池 `acquire_timeout` 只覆盖取连接。设计取 `max_connections=8`、`acquire_timeout=5s`，与现有等待预算同量级。
4. **PG 不可用**：Hub 启动即失败（连接探测在 `open` 阶段执行 `SELECT 1`）——快败优于半启动；运行中连接故障由 sqlx 池自动重连，命令错误经既有 `StorageError` 路径返回（Hub API 返回 5xx，Agent 侧重连逻辑已存在，数据面不受影响——符合 architecture.md §4）。

## 6. 配置面与部署

- `ARKFLOW_HUB_STORAGE` 分派：值以 `postgres://` / `postgresql://` 开头 → PG；否则视为 SQLite 路径（现状零破坏）。`ServerConfig` 结构体注释同步。
- 连接串选项（池大小、超时）v1 不暴露独立配置键，避免配置面膨胀；需要时走 PG URL 参数（`?max_connections=8` 由代码解析或后续迭代）。
- Kubernetes/部署文档更新归入实施 change（deploy.md en/zh）。

## 7. 数据迁移工具

`arkflow-server migrate --from sqlite:<path> --to postgres:<url>`（argv 子命令，与现有 env 风格并存）：

1. 打开两端；PG 先执行幂等 DDL（空库）。
2. 表级拷贝顺序 = 外键依赖序（cp_config_versions 自引用先于引用者；其余表无跨表 FK）：按 `[cp_nodes, cp_jobs, cp_job_versions, cp_job_tasks, cp_job_checkpoints, cp_config_versions, cp_intents, cp_stream_desired, cp_stream_observed, cp_attempts, cp_events, cp_audit_events, cp_rollouts, cp_rollout_targets, cp_operations, cp_outbox]` 逐表全量读出、分块（1000 行/事务）写入。
3. 自增表迁移后用 `setval` 重置 IDENTITY 序列为 `max(event_id)`。
4. 校验：逐表行数对账 + 抽样主键存在性；不一致即非零退出。
5. 迁移期间要求 Hub 停写（文档明示：先停 Hub，再迁移，再切换 `ARKFLOW_HUB_STORAGE` 指向）。

## 8. 测试策略

- **契约套件参数化**：现有 storage 单测的断言体抽为 `async fn assert_contract(backend)`；SQLite 全量跑（现状不变），PG 在 `ARKFLOW_TEST_POSTGRES_URL` 存在时跑同一套（无该变量则 `#[ignore]`——与 pgvector live 测试同模式）。
- **离线文本断言**：PG DDL/查询语句的文本断言（幂等 DDL 可重复执行、冲突映射 SQL）无需真实库即可跑 CI。
- **迁移工具测试**：内存 SQLite（填充已知数据）→ 临时 PG（门控）断言行数与抽样值；无 PG 时 `#[ignore]`。
- **对拍测试**（可选加分项）：同一命令序列分别灌入两后端，比对最终状态 JSON。

## 9. 实施任务分解（供 `add-hub-postgres-storage` 立项取用）

1. `StorageBackend` trait 抽取 + SQLite 实现搬移（不改行为，全量测试绿）。
2. PG DDL + `PostgresBackend` 实现（含 `RETURNING`、冲突映射、COLLATE "C"）。
3. 入口 scheme 分派 + `StorageError::Pool`。
4. 契约套件参数化 + PG 门控测试。
5. `migrate` 子命令 + 迁移测试。
6. 文档（deploy.md en/zh、PLANNING）+ 归档。
预估规模：storage.rs 触碰面 ~2500 行，新文件 1-2 个，与 wasm processor change 同量级或略大。

## 10. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 方言差异导致隐性语义漂移（时间戳整数比较、COLLATE） | §4 显式 COLLATE "C"；契约套件双跑 |
| 52 命令逐一改造引入笔误 | 第 1 步纯搬移零行为提交，编译器+现有测试兜底；后续步骤独立提交 |
| PG 仅在集成环境可得，CI 覆盖不足 | 门控 live 测试 + 文本断言离线跑；merge 前 maintainer 手动跑一轮 PG 契约套件 |
| outbox 顺序在 PG 并发下漂移 | actor FIFO 保持，命令仍逐条 await（§3） |

## 11. 决策记录

| 决策 | 结论 | 理由 |
|------|------|------|
| async trait vs 同步 PG 驱动 | async_trait + sqlx PgPool | actor 本就是 tokio 任务；避免引入第二 PG 驱动 |
| actor 去留 | 保留 FIFO | 顺序语义是 reconciliation/outbox 的隐含契约 |
| 配置面 | `ARKFLOW_HUB_STORAGE` scheme 分派 | 零新配置键，向后兼容 |
| IDENTITY vs BIGSERIAL | `GENERATED BY DEFAULT AS IDENTITY` | SQL 标准显式覆盖隐式插入路径 |
| DDL 管理 | 代码内幂等 DDL（同现状） | 不引入 sqlx migrate 机制，演化方式与 SQLite 侧一致 |
