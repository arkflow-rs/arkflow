# Capability: Hub 高可用

## Purpose

Hub 当前为单实例部署（SQLite 单写者、无故障转移）。本 capability 记录 HA 演进的决策与蓝图：`architecture.md` 是选项调研（选主机制、存储后端、Agent 重连、迁移路径），`postgres-storage-design.md` 是阶段 1（存储迁移）的实施蓝图。

## Requirements

### Requirement: HA 架构设计文档

SHALL 产出架构设计文档，覆盖 leader election 机制对比（Raft / 外部协调服务 / DB 租约）、存储后端选项（SQLite WAL / PostgreSQL / etcd）、Agent 重连策略、数据面不受影响的保证。

#### Scenario: 设计文档覆盖全部 HA 架构决策维度

- **WHEN** 查阅 HA 架构设计文档
- **THEN** 包含架构选项对比表、推荐方案及理由、迁移路径说明

### Requirement: PostgreSQL 存储后端设计文档

SHALL 产出阶段 1（SQLite→PostgreSQL）的评审级设计文档，覆盖：backend 抽象与 actor 顺序不变性、17 张 `cp_*` 表的类型/索引映射、`ARKFLOW_HUB_STORAGE` scheme 分派的向后兼容配置面、一次性数据迁移工具、事务与唯一约束语义映射、双后端契约测试策略、风险与决策记录。

#### Scenario: 设计文档可支撑实施立项

- **WHEN** 查阅 postgres-storage-design 设计文档
- **THEN** 包含 backend trait 签名级定义、逐表映射表、迁移工具命令行契约、测试门控方式与实施任务分解

### Requirement: Hub storage SHALL support a PostgreSQL backend behind one contract

The Hub control-plane store SHALL expose a `StorageBackend` contract implemented by both the default SQLite backend and a PostgreSQL backend (sqlx pool). The `ARKFLOW_HUB_STORAGE` value SHALL dispatch by scheme — values starting with `postgres://` or `postgresql://` open the PostgreSQL backend (with a startup connectivity probe that fails fast), any other value is treated as a SQLite file path with today's behavior unchanged. The storage actor SHALL process commands strictly FIFO against either backend, preserving operation ordering semantics. A PostgreSQL backend SHALL use idempotent startup DDL covering every `cp_*` table (BIGINT for epoch-ms/counters/generations, `GENERATED BY DEFAULT AS IDENTITY` for autoincrement keys, `COLLATE "C"` on TEXT primary/unique columns, partial unique indexes translated verbatim) so an empty database converges on startup.

#### Scenario: Scheme dispatch opens the matching backend

- **WHEN** `ARKFLOW_HUB_STORAGE` is set to `postgres://user:pass@host/hub`
- **THEN** the Hub opens a PostgreSQL-backed store, probes connectivity at startup, and fails startup (rather than serving half-open) when the database is unreachable

#### Scenario: Plain path keeps SQLite behavior

- **WHEN** `ARKFLOW_HUB_STORAGE` is set to a filesystem path or left unset
- **THEN** the Hub opens the SQLite store with today's pragmas and zero behavior change

#### Scenario: FIFO ordering is backend-independent

- **WHEN** the same sequence of storage commands is applied to either backend
- **THEN** the actor applies them in submission order and reconciliation/outbox semantics observe the same ordering

### Requirement: Dialect differences SHALL map onto the existing domain errors

The PostgreSQL backend SHALL translate unique-constraint failures (SQLSTATE 23505) onto the same domain errors the SQLite backend produces (intent idempotency reuse, attempt command dedup, outbox event-key dedup), so callers cannot observe which backend is in use from error variants. Autoincrement retrieval SHALL use `RETURNING` instead of SQLite's `last_insert_rowid`. Unsigned 64-bit values SHALL be stored as BIGINT with explicit casts on bind and read.

#### Scenario: Idempotency-key reuse reports the same error on both backends

- **WHEN** the same idempotency key is reused with a different payload on either backend
- **THEN** the caller receives the same `IdempotencyKeyReused` domain error

### Requirement: One-shot migration from SQLite to PostgreSQL

The server binary SHALL provide a `migrate` subcommand (`--from sqlite:<path> --to postgres:<url>`) that copies every `cp_*` table in foreign-key order in bounded chunks, resets IDENTITY sequences to each table's max id, verifies per-table row counts, and exits non-zero on any mismatch. Migration requires the Hub to be stopped (documented); the tool SHALL NOT be required for fresh PostgreSQL deployments.

#### Scenario: Migration round-trips row counts

- **WHEN** a populated SQLite Hub store is migrated to an empty PostgreSQL database
- **THEN** every table's row count matches the source and the identity sequences continue above the migrated max ids

### Requirement: Storage contract tests SHALL run against both backends

The storage contract suite SHALL be parameterized over the backend abstraction: SQLite runs in full offline CI; PostgreSQL runs the same suite when `ARKFLOW_TEST_POSTGRES_URL` is set and is skipped otherwise.

#### Scenario: Contract suite gates both backends

- **WHEN** CI runs with `ARKFLOW_TEST_POSTGRES_URL` pointing at a disposable PostgreSQL instance
- **THEN** every contract assertion executes against the PostgreSQL backend with the same expected outcomes as SQLite
