# Design: add-remote-transparent-reconnect

## 关键决策

1. **重放集 = 未回执集**：`PendingReceipts` 条目在回执完成时移除，天然就是重放集——已确认帧永不重放，无单独日志。
2. **复用原 seq**：重放帧保留注册时的 seq，接收端 `delivered_seq`（按会话键的最大已投递 seq）即可判重；重置 seq 将无法区分"新帧"与"重放"。
3. **镜像补发 Acked**：被去重丢弃的帧必须补发回执——原回执可能随断连丢失，不补发则上游分支悬置到 drain 超时；上游 `apply` 幂等（未知 seq 丢弃）使双回执安全。
4. **宽限判定用注册代数**：`session_registrations` 每次连接成功路由 +1；丢连观察者比对快照，变更即恢复。不用时间戳，避免时钟假设。
5. **泵的排空后半程存活**：排空后读循环继续（既有不变量：晚到回执必须能落地）；监督循环仅在读任务自然结束后做最终清理——这条是调试中抓到的回归（提前取消丢回执），已用 TCP 端到端测试钉住。
6. **确定性错误也走预算**：编码失败等确定性错误重放必然复现 → 烧完预算 → fail-closed，语义安全（浪费有界）。

## 风险

- 重连窗口与 checkpoint 超时的交互：断连窗口内 barrier drain 超时仍失败该轮（保守）；恢复后下一轮继续。
- 宽限期注册表保留延长了陈旧会话键的存活（上限 = grace 时长），由确认丢失任务与 remove_job_session 双路径清理。
