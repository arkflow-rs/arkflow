## Why

ArkFlow's documentation is growing faster than its navigation and publishing system: the site currently exposes one autogenerated sidebar (`docs/sidebars.ts:23-24`), while the source tree mixes getting started, concepts, configuration, components, SQL, control-plane operations, deployment, and historical versions without a clear user journey. The documentation package also has only development/build scripts (`docs/package.json:5-17`) and Docusaurus merely warns on broken Markdown links (`docs/docusaurus.config.ts:38-41`), so reference drift and incomplete workflows can reach production.

ArkFlow now spans stream processing, durability, delivery semantics, a control plane, many plugins, and production operations. It needs a docs system with the information architecture, discoverability, generated references, version policy, validation gates, and contribution workflow expected of a mature infrastructure project.

## What Changes

- Establish a task-oriented information architecture for newcomers, operators, developers, and component users, with explicit landing pages and curated sidebars.
- Rework the home, README links, navigation, and version presentation so users can reach installation, quickstart, configuration, component reference, concepts, operations, and API material predictably.
- Introduce a documentation content contract covering page metadata, naming, headings, examples, configuration snippets, cross-links, deprecation notices, and ownership.
- Add generated or checked reference surfaces for supported components and configuration, sourced from the implementation or a single declared registry where practical.
- Add repository-local documentation checks for front matter/metadata, sidebar reachability, internal links and anchors, code/config examples, component coverage, and stale versioned content.
- Define release and versioning rules, including current versus archived docs, compatibility notices, and a documented process for updating versioned pages.
- Add contributor and maintainer guidance for authoring, review, local preview, validation, and release-time documentation sign-off.
- **BREAKING**: replace the current implicit autogenerated navigation with an explicit curated navigation contract and move or rename pages as needed to match the new information architecture.

## Non-goals

- Rewriting every technical page's content in this change; content migration will prioritize correctness, entry points, and high-value workflows, with remaining pages moved under the new structure.
- Introducing a new documentation hosting provider or abandoning Docusaurus.
- Changing ArkFlow runtime behavior, configuration semantics, public APIs, or plugin support solely to satisfy documentation structure.
- Providing a complete translation system; internationalization can follow after the English information architecture and validation contract are stable.

## Capabilities

### New Capabilities

- `documentation-information-architecture`: Curated, persona- and task-oriented navigation and page taxonomy for the public documentation site.
- `documentation-content-contract`: Authoring conventions and required metadata/content structure for trustworthy ArkFlow documentation.
- `documentation-reference-generation`: Repeatable generation or validation of component and configuration reference content from canonical project data.
- `documentation-quality-gates`: Automated checks and CI enforcement for links, anchors, examples, metadata, coverage, and version hygiene.
- `documentation-release-lifecycle`: Versioning, archival, compatibility labeling, and release checklist rules for documentation.

### Modified Capabilities

- None. This change introduces documentation-system contracts; it does not alter an existing runtime capability requirement.

## Impact

- `docs/` content, Docusaurus configuration, sidebars, theme/navigation, scripts, package scripts, and versioned documentation.
- Root `README.md`, `README_zh.md`, documentation contributor guidance, and likely CI workflow files under `.github/workflows/`.
- Potentially component/configuration metadata or small extraction utilities needed to keep references canonical.
- Documentation build and review workflows for contributors and release maintainers; no runtime dependency or API contract changes are intended.
