## Context

The Hub is env-driven (`arkflow-server.rs:26-46`): `ARKFLOW_HUB_ADDRESS`, `ARKFLOW_NODE_TOKEN` (shared registration credential), `ARKFLOW_OPERATOR_TOKEN`, `ARKFLOW_HUB_STORAGE` (filesystem path = SQLite, `postgres://` = Postgres), TLS and HA envs. The Console image already exists with a same-origin nginx proxy, but its upstream is hard-coded to `arkflow-hub:8080` (`console/nginx.conf`), which only matches one possible release name. The engine chart from `add-helm-chart` already renders standalone/agent modes with pass-through config and single-replica semantics; this change grows the same chart rather than adding a second one.

## Goals / Non-Goals

**Goals:**

- Containerized, CI-published Hub and Console images installable by one `helm install` in `mode: control-plane`.
- SQLite-on-PVC default storage with a documented `postgres://` opt-in — matching the deploy docs' storage contract.
- One shared node credential flowing to both Hub and in-chart agent by default.
- Zero changes to existing standalone/agent renders (CI-asserted).

**Non-Goals:** operator/CRDs, cert-manager/mTLS, Hub HA orchestration, Vite build channels beyond the existing token (see proposal).

## Decisions

### D1: One chart, three modes — `controlPlane.*` values namespace

`mode: control-plane` renders Hub + Console (+ optional agent) alongside the existing modes' surfaces. A separate chart was rejected: it would duplicate the agent templates and the values philosophy, and users installing a fleet want one release. The existing `agent.*` values are reused by the control-plane agent; `config` supplies its engine document with `hub_urls` defaulting (in values) to the in-chart Hub service.

### D2: Console upstream via nginx envsubst template

`console/nginx.conf` moves to `console/nginx.default.conf.template` with `proxy_pass ${ARKFLOW_HUB_UPSTREAM}` (default `http://arkflow-hub:8080`, resolved at container start by nginx's built-in envsubst entrypoint). The chart sets `ARKFLOW_HUB_UPSTREAM=http://<release>-hub:8080`. Build-time ARGs were rejected (upstream would be baked per image); init-container sidecars were rejected (nginx templates are native and zero-cost).

### D3: Hub storage — SQLite on PVC by default

Default `ARKFLOW_HUB_STORAGE=/var/lib/arkflow/hub.sqlite` on the same `persistence.*` PVC mechanism (enabled by default in control-plane mode, unlike standalone where it stays opt-in). `controlPlane.hub.storage.postgresURL` (env-expanded `${env:...}` allowed) switches to Postgres and disables the PVC. Migration between them stays a manual `arkflow-server migrate` operation per the deploy docs.

### D4: Shared node credential generated by the chart

`controlPlane.nodeToken.secretRef` (user Secret) or, by default, the chart renders a Secret with `randAlphaNum 32` on first install (`helm.sh/resource-policy: keep` so upgrades never rotate it silently). The same key feeds `ARKFLOW_NODE_TOKEN` on the Hub and on the in-chart agent. Chart-side generation was chosen over requiring a user Secret because agent+Hub must match and a missing default would render a fleet that cannot register; `keep` guards against credential rotation surprises.

### D5: Hub Deployment stays single-replica

SQLite/PVC is ReadWriteOnce and the Hub's HA requires Postgres leases anyway; the Deployment uses `Recreate` (same reasoning as the engine: never two Hubs against one store). Users pointing at Postgres may scale manually — documented, not orchestrated.

### D6: Docker matrix in the existing workflow

`docker.yml` `build` job becomes a 3-entry matrix (engine `docker/Dockerfile` ctx `.`, server `docker/Dockerfile.server` ctx `.`, console `console/Dockerfile` ctx `./console`). Per-image buildcache refs (`…:buildcache-server`, `…:buildcache-console`); disk-space/swap/cosign steps apply to Rust images only (condition on `matrix.rust == true`); cosign signs all three digests.

## Risks / Trade-offs

- [Matrix triples the workflow's Rust build time on tag pushes (two LTO builds in parallel)] → parallel matrix jobs, each with its own runner and swap; wall time roughly unchanged.
- [Chart-generated Secret with `keep` policy survives `helm uninstall`] → deliberate (protects stateful reuse); documented in NOTES.txt with the deletion command.
- [Console image now depends on nginx template env at runtime] → default env preserves byte-equivalent behavior for non-chart users (`arkflow-hub:8080`).
- [Hub image runtime deps mirror the engine's (python3/sqlite)] → slight image bloat accepted; the hub links the same core crate and the safe superset avoids a missing-.so class of failures.

## Migration Plan

New images and chart mode only. Existing standalone/agent releases are untouched (CI asserts byte-stable renders). Rollback: `helm uninstall`; images are additive.
