## Context

The docs site is a Docusaurus app (`docs/`) with a single-locale stub already in place (`docusaurus.config.ts:50-53`, `locales: ['en']`), three versioned snapshot trees, a bespoke ~1047-line landing page (`src/pages/index.tsx`), and a strict local/CI gate (`pnpm docs:check`, `scripts/docs-check.mjs`) that validates front matter, H1s, internal links/anchors, example registration, YAML-block classification, sidebar reachability, and README parity — all against the English tree only. English is canonical (maintainer decision): the Chinese locale is a pure translation layer that must never fork content policy, URL structure, or the release workflow. The repo already carries a Chinese README (`README_zh.md`), so a zh audience is established.

Docusaurus i18n semantics are the backbone: untranslated content in a non-default locale build falls back to the default-locale content, and routes are prefixed (`/zh-Hans/docs/...`) while the default locale stays at root. This makes progressive, page-by-page translation viable without a "translation complete" milestone.

## Goals / Non-Goals

**Goals:**
- Register `zh-Hans` as a secondary locale with fallback-to-English semantics; `en` stays the default locale at `/`.
- Localized site chrome (navbar, footer, announcement bar, tagline) and landing page so switching locales visibly changes the site.
- Working local search for both locales (CJK tokenization).
- Translate the first-mile set (~15 pages): get-started, getting-started, concepts, and the core build-concept pages (jobs, streams, architecture).
- Extend the quality gate so the zh tree cannot rot silently: front-matter parity, link/anchor validity under fallback semantics, YAML-block fidelity.
- Codify the drift policy in `docs/DOCUMENTATION.md`.

**Non-Goals:**
- No translation of versioned trees, blog, or Tier-2/3 content (components/, sql/, reference/, operate/, how-to/, develop/, cases/, tutorials/, migration/, configuration/, control-plane/, deploy/, about/).
- No staleness-report CI, machine translation, Crowdin-style platform, default-locale change, or URL restructure.
- No Rust-side changes; the workspace snippet validator keeps reading `docs/docs/` only.

## Decisions

### D1. Built-in Docusaurus i18n with fallback — not a second site, not big-bang translation

Alternatives: (a) a separate Chinese Docusaurus instance/site, (b) translating all 128 pages before launch. (a) duplicates theme, search, checks, and release workflow, and forks content policy; (b) is months of work before any user sees value. Built-in i18n gives the fallback model for free: every untranslated route still renders (in English) at `/zh-Hans/`, so partial translation is a supported steady state, not a broken one. Surgical-change rule satisfied: English sources are untouched.

### D2. Locale code `zh-Hans`, not `zh`

`zh-Hans` encodes Simplified Chinese explicitly, yields a correct `html lang="zh-Hans"`, and is Docusaurus's own suggested convention (the config stub's comment). `zh` would only match the `README_zh.md` filename convention, which is a repo file naming habit, not a URL. The locale code is effectively permanent once URLs ship, so precision wins. URL impact: `/zh-Hans/docs/...`.

### D3. Landing page: localized copy, not `<Translate>` wrapping

Alternatives: (a) wrap all strings in `src/pages/index.tsx` (1047 lines) with `<Translate>` + `code.json`, (b) copy the page into `i18n/zh-Hans/docusaurus-plugin-content-pages/` and edit strings in the copy. (a) is the Docusaurus-recommended single-source approach but means mechanically touching a large bespoke file with JSX interpolation — high review surface, real regression risk, and the file gets harder to edit thereafter. (b) touches zero English lines, ships immediately, and landing pages change rarely enough that copy drift is manageable; it is consistent with the surgical-change rule. Site chrome (navbar/footer labels, sidebar categories) needs no code change — theme/plugin JSON files generated by `docusaurus write-translations`; the theme ships built-in `zh-Hans` UI strings, so only project-specific labels are overridden. For config-level strings (tagline, announcement bar), the `translate()` helper documented for configs is not loadable there in 3.9.2 (`@docusaurus/Translate` is a webpack-only alias; the config loads via jiti outside alias space), so we adopt the mechanism the official Docusaurus site itself uses: a `docusaurus.config.localized.json` keyed by locale, resolved through the `DOCUSAURUS_CURRENT_LOCALE` env var that `buildLocale`/`start` set per build.

### D4. `docs:check` extends to the zh tree with fallback-aware semantics

New checker section walks `docs/i18n/zh-Hans/docusaurus-plugin-content-docs/current/**` and reuses the existing slug/anchor/link helpers:

- **Counterpart existence**: every zh page must have an English page at the mirrored path under `docs/docs/`; a zh page whose counterpart was moved/deleted fails the gate (catches structural drift).
- **Front-matter parity**: `id`, `slug`, `sidebar_position`, `sidebar_label` (when present), and the `components:` ownership list must equal the English counterpart's; `title`, `description` SHOULD differ (they are the translation). Same ids keep the shared sidebar and ownership checks valid.
- **Links and anchors**: file-relative links are validated against the localized tree only — the production build (`onBrokenMarkdownLinks: throw`) resolves file-relative links within the localized tree and cannot fall back, so the checker mirrors that. Links to untranslated pages use locale-prefixed absolute routes (`/zh-Hans/docs/...`, skipped like any absolute URL, same policy as the English tree); untranslated content renders as English fallback at those routes, so the user never leaves the locale. The resolution rule is symmetric, so the checker also pre-detects the inverse case in English sources: an untranslated English page using a file-relative link to a page that has a localized counterpart breaks the localized build (the target registers under its localized source path), and such links must use their absolute `/docs/...` route instead — the gate converts a cryptic build error into actionable guidance.
- **YAML-block fidelity**: every ` ```yaml ` fence in a zh page must be byte-identical to the corresponding fence in the English counterpart — metastring (the `validate=` classification marker) and content. Code blocks are not translated; this makes the zh tree snippet-valid by construction without extending the Rust-side validator.
- **Sidebar reachability** stays English-only: front-matter parity guarantees zh pages inherit the same ids, hence the same sidebar membership.

Gate mechanics stay as-is: same command (`pnpm docs:check`), same failure style (file + reason list, non-zero exit), no duplicate checker implementation.

### D5. Search: enable bilingual tokenization in docusaurus-search-local

Set `language: ['en', 'zh']` on the `@easyops-cn/docusaurus-search-local` theme config. The plugin ships CJK segmentation and handles mixed CJK/Latin queries; each locale build gets its own index from its own rendered content (so the zh index naturally contains translated pages plus English fallback pages). No Algolia dependency is introduced.

### D6. Drift policy: allowed lag, enforced structure

English is the single upstream. Contributors editing an English page that has a zh counterpart are asked (DOCUMENTATION.md convention, not a gate) to update or note the translation; content staleness is accepted and unblocked. What the gate enforces is structural: counterpart existence, front-matter parity, YAML fidelity. A CI staleness report is deferred until zh coverage exceeds ~50 pages.

## Risks / Trade-offs

- [English edits silently stale translated pages] → Accepted for content (policy D6); structure is gate-enforced (D4). Revisit staleness report at >50 translated pages.
- [Landing page copy drifts from English original] → Accepted (D3); landing changes are infrequent and review-visible. If drift becomes a problem, migrate to `<Translate>` later without URL impact.
- [zh build lengthens CI] → `pnpm build` now builds both locales (~2x docs build). Acceptable at current page count; if it bites, CI can split locale builds via `--locale` without repo changes.
- [search-local CJK quality unknown in practice] → Early spike task verifies zh segmentation and mixed-language queries on the rendered site; worst case is degraded zh search relevance, not breakage; English search unaffected.
- [Translators "improving" YAML examples or front matter] → Byte-fidelity gate (D4) rejects the PR mechanically; DOCUMENTATION.md states the rule.
- [Fallback hides missing translations from translators] → The zh tree is small and enumerated in DOCUMENTATION.md; a later Tier-2 change can add a coverage page/report if wanted. Not a correctness risk for users.

## Migration Plan

Additive, single change, no data or URL migration:

1. Infra: locales + `translate()` config strings + theme/code JSONs + search language; `pnpm build` must pass both locales.
2. Landing copy + chrome translations; locale switcher becomes visibly functional.
3. First-mile pages translated (any order; each page independently useful due to fallback).
4. Checker extension lands with (or before) the first translated page so the zh tree is never ungated.
5. DOCUMENTATION.md policy section.

Rollback: remove `zh-Hans` from `locales` — the zh tree and JSON files become inert data; English site and all gates revert to today's behavior.

## Open Questions

None blocking. Tier-2 trigger (translate components/sql/reference + staleness report) is intentionally left to a future change; the expected trigger is zh coverage demand plus >50 translated pages.
