## Why

ArkFlow's user-facing docs are written for users who have *already* chosen the
engine — they are configuration how-to pages. Surveying the dominant competing
products (Vector, Benthos, RisingWave, Flink) reveals structural gaps that
cost us evaluation-stage readers:

- No **Cookbook / Recipes**: Benthos's highest-converting section, absent
  entirely. `docs/docs/` has no recipes directory.
- No **Migration** guide: RisingWave's signature page; ArkFlow has none
  (nothing under `docs/docs/` mentions migrating from Vector/Benthos/Flink).
- No **Observability** chapter: every mature product documents metrics /
  tracing / health. ArkFlow has Prometheus deps in `Cargo.toml` but no docs
  section.
- No **Troubleshooting / FAQ**: standard for any production tool, missing.
- **Concepts** (`docs/docs/concepts/`) is almost entirely reliability topics
  — `1-architecture`, `2-backpressure-ordering`, `3-metadata`,
  `4-delivery-semantics`, `5-wal-optimization`, `6-exactly-once` — with zero
  coverage of mainstream stream-processing concepts (Time / Window / State)
  that Flink and RisingWave teach in depth.
- **Component docs** (`docs/docs/components/0-inputs/kafka.md` and siblings)
  use a thin three-part template (config table + 1–2 examples + Notes),
  whereas Vector's per-component docs are the industry bar: Status, When to
  use, multi-scenario examples, output schema, metrics, see-also.
- **Orphan file**: `docs/performance/s3-wal-backend.md` is not surfaced in
  the sidebar — `docs/sidebars.ts` uses `autogenerated` against `dirName:
  '.'`, but `performance/` sits beside (not under) the content `docs/`
  directory, so the page is silently dropped.
- **No "Why ArkFlow" positioning**: `openspec/PLANNING.md` fixes the
  strategic niche as "Benthos's shape + production-grade reliability +
  columnar SQL", yet the docs have no comparison page expressing this.

The docs drifted thin after the reliability and control-plane work landed;
this change realigns IA and content depth to the bar set by market leaders,
without touching engine code.

## What Changes

- **Rebuild top-level IA** to 12 sections: Introduction (+ Why/comparison) ·
  Getting Started (+ CLI reference, + first real pipeline) · Concepts
  (expanded with Time/Window/State) · Configuration (+ embedded JSON Schema)
  · Components (new template) · SQL Reference · Processing Guides **(NEW)** ·
  Cookbook **(NEW)** · Observability **(NEW)** · Operations (K8s + control
  plane + absorbed `performance/`) · Troubleshooting **(NEW)** · Migration
  **(NEW)**.
- **Standardize a Vector-grade component-doc template** (Status · When to use
  & not · Common fields · Full reference with `default`/`common?` columns ·
  multi-scenario Examples · Output schema · Error handling · Metrics · See
  also) and apply it across all inputs/outputs/processors/buffers/codecs.
- **Semi-automate component config tables** from `arkflow schema` and
  `arkflow components show <kind> <name> --format json` to prevent
  docs-vs-code drift.
- **Absorb `docs/performance/`** into the Operations section so no doc page
  is orphaned.
- **Add a "Why ArkFlow" comparison** page against Vector / Benthos / Flink /
  RisingWave, aligned to the niche in `openspec/PLANNING.md`.
- Reorganize via Docusaurus `_category_.json` ordering and an explicit
  `sidebars.ts` (keeping `autogenerated` only where ordering is fully
  `sidebar_position`-driven).

## Capabilities

### New Capabilities

- `docs-information-architecture`: The set of top-level documentation sections
  that MUST exist, the ordering invariants, and the zero-orphan-pages rule
  (every markdown file under the docs content root SHALL be reachable from
  the sidebar).
- `docs-component-template`: The mandatory subsections of every component
  reference page and the requirement that every config field table stays
  consistent with the CLI-emitted schema.

### Modified Capabilities

- `documentation-accuracy`: Extends existing truthfulness requirements to
  cover (a) the component inventory shown in docs SHALL match
  `arkflow components list`, and (b) every component's documented config
  fields SHALL match `arkflow components show <kind> <name> --format json` /
  `arkflow schema`, so drift is detectable and preventable.

## Non-goals

- No changes to Rust code, config-schema behavior, or engine semantics — this
  is a docs-only change.
- No i18n / Chinese-language site (kept as a separate future change; English
  remains primary).
- No AI/ML-related documentation (`openspec/PLANNING.md` treats that as an
  independent direction).
- No rewrite of the SQL reference — only minor edits plus a streaming-SQL
  supplement.
- This change does NOT produce all ~70 pages of final content in one shot.
  It fixes the IA skeleton, the template contract, and a high-priority first
  batch; remaining pages land via subsequent apply passes against the same
  tasks.md.

## Impact

- **Files**: `docs/docs/**` (reorganized), `docs/sidebars.ts`,
  `docs/docs/**/_category_.json`, `docs/performance/**` (moved into
  `docs/docs/operations/`), new directories under `docs/docs/` for cookbook,
  observability, troubleshooting, migration, processing guides.
- **Tooling**: a small script (or Makefile target) that regenerates component
  config tables from `arkflow components show --format json`, run in CI/docs
  build to enforce schema consistency.
- **Build**: `docusaurus build` MUST pass with zero broken links;
  `onBrokenLinks: 'throw'` in `docs/docusaurus.config.ts` already enforces
  this.
- **No code or dependency impact**: `Cargo.toml`, crate sources, and the
  binary are untouched.
