# Web 控制台

控制台是 Hub 运维 API 的图形前端。它以 Vite + React 单页应用的形式随仓库发布在
`console/` 目录下,由 Hub 旁边的反向代理提供服务——构建与服务方式见
[部署](./deploy.md)。

## 视图

| 视图 | 展示内容 |
|------|---------------|
| **概览** | 机群健康优先:节点上下线摘要、收敛状态以及指向问题区域的入口。 |
| **作业** | 作业目录,包含期望与观测状态、版本、暂停相位以及生命周期操作(启动/停止、暂停/恢复、检查点、升级)。 |
| **作业编辑器** | 基于表单的作业规格编辑器,提交前会校验规格。 |
| **作业 DAG** | 作业算子图的有向图编排视图——算子边界、分区路由与有状态算子,对应 `GET /api/v1/jobs/{id}/plan`。 |
| **灰度发布** | 按节点展示的灰度发布进度,支持暂停、恢复、取消与回滚操作。 |
| **运行时** | 基于节点上报的实时每节点流状态与收敛情况。 |
| **组件** | 组件注册表浏览器:展示每个注册的 kind/type 及其配置 schema 与示例,对应 `arkflow components show`。 |
| **配置** | 节点配置历史、差异对比、应用与回滚。Hub 模式下所有操作都经由所选节点路由;草稿是本地控制面功能。 |
| **事件** | 机群事件日志(`GET /api/v1/events`,附带用于实时更新的 SSE 流),过滤与分页均在服务端执行。 |
| **审计** | 机群审计历史(`GET /api/v1/audit`):已接受与被拒绝的变更,携带操作者、目标、节点与结果,支持按资源过滤并在服务端分页。 |
| **用户** | 托管用户目录与凭证页(`/users`):用户、角色、scope、OIDC 绑定,一次性凭证签发、轮换、吊销与令牌吊销。仅在 Hub 模式且主体持有 `manage_users`(admin)时可见。 |
| **设置** | 控制台偏好、连接设置与运行期 Bearer 凭证面板。 |

## 按照 API 的工作方式理解控制台

控制台是期望状态 API 之上的瘦客户端,其视图将三种资源视图明确区分:

- **期望(Desired)**——你想要的状态(刚保存的 Intent)。
- **观测(Observed)**——节点最近一次上报的状态。
- **收敛(Convergence)**——两者是否一致(`in_sync`、`pending`、`applying`、
  `degraded`、`blocked`)。

绿色徽标表示已收敛,而不是“命令已成功”:点击某个操作后,控制台会显示该待完成操作,直到对应的节点上报到达。
如果节点离线,操作仍会被接受(Intent 是持久的),视图会把该操作显示为阻塞,直到节点重连。

当 Hub 声明高可用状态时,控制台会展示机群的高可用姿态:概览卡片显示领导角色(leader 或 standby)、租约纪元与切换次数。当所连 Hub 为备用节点导致所有请求被拒绝(503 `hub_standby`)时,控制台会用明确的备用提示取代通用的过期横幅,并持续轮询——该 Hub 赢得租约后提示会自动消失。诊断数据保持诚实:作业详情只渲染 API 实际度量的指标;任务页签区分观测到的运行时状态与尚未上报的期望放置。作业编辑器将分布式运行时字段——并行度变化时重分布键控状态的 `rescale` 开关,以及参与放置核算的每任务 `resources` 请求(`cpu_millicores`、`memory_bytes`)——作为表单控件提供,清空后按缺省形态序列化。

## 作业暂停与恢复

作业列表与详情面板对已收敛的运行中作业提供**暂停**入口,对暂停中的作业提供**恢复**入口,并以相位徽标把过渡状态显示出来(`capturing`、`stopping`、`paused`、`resuming`),而不是把它并入「已停止」。暂停或恢复过渡在进行的期间,操作按钮会被禁用;暂停行的任务列表把任务显示为「未观测」,而不是沿用陈旧的 running 状态。这些控件与启动/停止一样需要 `operate` 动作。确认文案会说明暂停会先落恢复工件再停机,以及 resume 会重放工件之后处理的事件;被拒绝的过渡会原样展示服务端的问题码(`pause_in_progress`、`job_already_paused`、`job_paused`、`orchestration_in_progress` 等)。在暂停中的作业上,`start` 与 `restart` 等价于 resume,`stop` 则把它落回 stopped。作业筛选器提供 `paused` 选项。服务端语义与重放边界参见[流式作业 → 暂停与恢复](/zh-Hans/docs/build/jobs#pause-and-resume)。

## 节点维护操作

概览卡片提供三个机群维护用的节点操作。每个操作触发前都会请求确认:

- **排空(Drain)**(`POST /api/v1/nodes/{id}/drain`)把该节点的分配迁往
  其他节点——在节点下线前使用。
- **维护(Maintain)**(`POST /api/v1/nodes/{id}/maintenance`)把节点标记为
  维护中,放置不再向它分配新任务。
- **恢复(Resume)**(`DELETE /api/v1/nodes/{id}/maintenance`)让节点回到
  现役状态。

节点不处于 `active` 状态时,其概览卡片会在节点名旁边以徽标显示当前状态
(`draining` 或 `maintenance`)。

## 导航与 URL

每个视图都有独立的 URL 路径(`/`、`/runtime`、`/jobs`、`/configuration`、
`/rollouts`、`/components`、`/events`、`/audit`、`/users`、`/settings`),因此视图可以
收藏、分享,并支持浏览器的前进/后退按钮。当前选中的计算节点以 `node_id`
查询参数的形式保存在当前路径上,切换视图时会自动保留。使用旧版 `?page=`
查询参数的历史链接(例如 `/?page=jobs`)会自动重定向到对应路径,并保留其余
查询参数。

导航只展示所连接控制面实际提供的能力。作业、灰度发布、审批、审计与用户视图依赖仅存在于 Hub 面的 API;当控制台连接的是本地引擎(`/system` capabilities 不含
`fleet_aggregation`)时,这些导航项不再出现,直接访问对应 URL 会渲染一段说明「需要 Hub」的解释页而非报错,Settings 也会隐藏 webhook 管理区。用户入口还额外要求 `manage_users` 动作,因此非 admin 主体永远看不到它。系统身份尚未加载完成时导航按全量渲染,避免启动时页面闪没。

事件与审计视图的过滤条件和页位置保存在 URL query 中(`event_type`、`stream_id`、`correlation_id`、`node_id`、`resource_id`、`page`、`page_size`):复制链接即可复现完全相同的视图,过滤与分页由服务端执行,修改任一过滤条件会回到第一页。每页条数可选 25 / 50 / 100 行。

## 身份与角色感知控制

`GET /api/v1/system` 会回显已认证的主体(Hub 面与本地平面均含 `principal: {id, roles, actions}`),控制台直接消费它:顶栏显示当前身份(例如 `ops (operator)`),所有可变更入口——流生命周期、配置发布/回滚、作业操作、灰度发布创建、审批决定、节点维护、webhook 管理、身份管理——都按回显的动作列表门控。缺少所需动作的主体会看到控件被禁用,并以 tooltip 标明所缺权限,因此 viewer 会话可以阅读一切但无法变更任何内容。回显来自与服务端授权变更相同的判定;若变更仍被 403 拒绝(例如角色在会话中途变化),控制台会显示权限错误、绝不自动重试,并刷新身份。面对不回显 principal 的旧控制面,控制台保持控件可用并将身份标记为未知,而不是把一切锁死。

## 用户与凭证 {#users-and-credentials}

在具备持久化存储的 Hub 上,控制台提供独立的**用户**页(`/users`),仅对持有
`manage_users` 动作(admin)的主体出现在导航中。它是
[用户与凭证 API](/zh-Hans/docs/reference/api#users-and-credentials)在控制台侧的对应物:

- **用户**:列出目录、创建用户(id、display name、逐项编辑的角色与 scope、可选 OIDC
  subject)、编辑、禁用/启用以及删除。每个变更动作都走标准确认对话框。
- **凭证**:查看凭证元数据(id、label、创建/过期/吊销时间戳),但绝不展示保存的
  哈希。签发凭证时明文 token 只展示一次,配复制按钮与明确的「仅显示一次」提示——
  控制台无法再次取回它,唯一的恢复方式是轮换。轮换同样只展示一次新 token;`DELETE`
  吊销是幂等的(`200` 响应体带 `{"revoked": bool}`,但 UI 不需要使用它)。
- **吊销令牌**:使该用户的联邦 JWT 与浏览器会话失效;托管凭证仍然有效,需要逐个
  吊销或轮换。
- 被拒绝的操作原样展示服务端问题码(`last_admin_required`、`credential_limit`、
  `oidc_subject_conflict`、`identity_store_unavailable` 等);`403` 走既有的权限
  降级路径。

该页有双重门控:Hub 模式(本地引擎没有用户目录)与 `/system` 回显包含
`manage_users`。其他主体看不到导航入口;直接访问会渲染「需要 Hub」的解释页,低权限
主体的直接请求会以服务端 `403 forbidden` 失败。

### 运行期 Bearer 凭证

控制台不再要求构建期注入 token。当 API 返回 `401` 且未配置 OIDC 登录流时,shell 会
提示输入 Bearer 凭证;**设置**页提供运行期凭证面板,含**切换凭证** / **清除凭证**
控件。输入的 token 保存在 `sessionStorage`——绝不使用 `localStorage`——因此关闭标签页
即消失,也不会跨标签页共享。存在 `VITE_API_TOKEN` 时它只是初始默认值;清除运行期凭证
后会回退到它。启用 OIDC 登录时,正常的跳转登录流程优先,不会使用运行期输入。

## 何时用控制台,何时用 API

- **控制台**:日常观测、单个作业的生命周期变更、灰度发布监控以及事件处置
  (事件 + 运行时 + 审计集中在一处)。
- **API**:自动化、GitOps 式配置交付以及任何需要可复现的操作——控制台的每个动作都是
  [HTTP API 参考](/zh-Hans/docs/reference/api)中有文档的路由。

## 主题

控制台内置深色(默认)与浅色两套主题,基于同一组设计令牌。顶栏的主题选择器提供
**深色 / 浅色 / 跟随系统** 三种选择;**跟随系统**会读取操作系统的偏好设置。
选择持久化在 `localStorage`(键 `arkflow.console.theme`)中,并在首次绘制前应用,
刷新页面不会出现主题闪屏。

破坏性与生命周期类操作通过应用内对话框确认(焦点圈闭,`Esc` 取消,`Enter` 确认),
操作结果以 Toast 通知反馈,表格在数据加载期间显示骨架屏。

## 界面语言

控制台界面内置英文与简体中文两套翻译。首次加载时,控制台根据浏览器语言
(`navigator.language`,任何 `zh*` 语言标签都会选中中文)自动选择,无法识别时回退英文。
顶栏的语言切换器(**中文 / English**)可即时切换,选择会持久化到 `localStorage`,
刷新后保持不变。日期与数字格式跟随所选语言。

后端返回的消息(API 错误、事件载荷)按原样展示,控制台不做翻译。

## 安全注意事项

控制台是一个静态资源包,除你输入的内容外不保存任何机密;它通过你的反向代理使用运维令牌向 Hub 认证。
运行期输入的 Bearer token 只在标签页生命周期内保存在 `sessionStorage`,绝不写入
`localStorage` 或 URL。一次性凭证展示只渲染那一次签发响应中的明文——控制台无法再次
取回。请将 Hub API 与控制台都放在经过认证、受保护的网络边界之后——不要把携带令牌的
部署暴露在公共互联网上(见[部署](./deploy.md))。
